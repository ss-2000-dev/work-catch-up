# Jiraの機能ガイド(SCM/PM向け)

対象読者:チケットの起票・管理は行っているが、フィルタ・ボード・ダッシュボード・自動化などの周辺機能をまだ使いこなせていない人。「毎回同じ検索条件を手入力している」「一括でステータスを変えられず1件ずつ開いている」といった状態からの脱却が目的。

各機能について、**何のためのものか / 使うために必要な権限**をセットで書く。権限はJira Cloudの「プロジェクト権限スキーム」に登場する権限名。

---

## 1. フィルタ(保存済み検索)

JQLや検索条件を保存して、毎回条件を打ち直さずに呼び出せる機能。「自分の担当チケット」「今スプリントの未完了」などをワンクリックで開けるようにする、最も基礎的な時短機能。

- 使い方:検索バーでJQLを入力 →「フィルタを保存」→ 名前を付ける。保存したフィルタは左サイドバーの「フィルタ」からいつでも呼び出せる
- チームで共有したい場合は、保存時の共有設定で対象プロジェクト/グループを指定する(自分だけの下書きフィルタと、チーム共有フィルタは分けておくと事故が少ない)
- 必要な権限:**「参照(Browse Projects)」** があれば自分用フィルタの作成・保存は可能。チームに共有するにはフィルタの共有先(プロジェクト/グループ)への参照権限が相手側にも必要

## 2. ボード(スクラム/カンバンボード)

チケットをステータスごとに列で見る画面。ドラッグ&ドロップでステータス変更ができる。

- ボードの列とワークフローのステータスは1:1で対応していないことがある(複数ステータスを1列にまとめられる)。列がやたら多い/少ないと感じたら、ボード設定の「列」でマッピングを確認する
- スイムレーン(担当者別・エピック別など)で分類して見ることができる。人ごとの偏りを見るときはスイムレーン=担当者にすると早い
- 必要な権限:ボード閲覧は**「参照」**で可能。ボード設定(列・スイムレーン・クイックフィルタの変更)には**「プロジェクトの管理(Administer Projects)」** が必要

## 3. クイックフィルタ(ボード上のワンクリック絞り込み)

ボードの上部に常設できるフィルタボタン。「自分の担当だけ」「バグだけ」のように、よく使う絞り込みをボタン化できる。

- ボード設定 →「クイックフィルタ」から追加。JQLの断片(例:`assignee = currentUser()`)を登録するだけでよい
- チームメンバー全員が使うボードなら、ここに主要な絞り込みを用意しておくとJQLを書けないメンバーも自走できる
- 必要な権限:**「プロジェクトの管理」**(ボード設定を変更するため)

## 4. ダッシュボードとガジェット

複数のフィルタ結果やチャートを1画面にまとめて表示する機能。朝会前に開く「進捗確認用の1画面」を作っておくと状況把握が速くなる。

- よく使うガジェット:「フィルタの結果」(保存済みフィルタをテーブル表示)、「2次元フィルタ統計」(担当者×ステータスなどのクロス集計)、「スプリントの健全性レポート」「バーンダウンチャート」
- ダッシュボードは自分専用と共有用を分けるのがおすすめ。共有用は関係者に見せる前提でシンプルに作る
- 必要な権限:ダッシュボード自体はJira全体の機能でプロジェクト権限に依存しないが、中で使うフィルタ/プロジェクトへの**「参照」**権限がないとガジェットにデータが出ない

## 5. 一括編集(Bulk Change)

検索結果に対して、複数チケットのステータス・担当者・ラベル等を一括変更できる機能。

- 検索結果一覧の「…(その他の操作)」→「一括変更」から実行。編集・遷移(ワークフロー変更)・削除・ウォッチ登録などが選べる
- 「このJQLに一致するチケットを全部クローズしたい」のような棚卖ぎ作業はここを使うと1件ずつ開く必要がない
- 必要な権限:対象操作に応じて個別に必要(例:ステータス変更なら**「課題の編集(Edit Issues)」**+**「課題のスケジュール」等の遷移条件**、削除なら**「課題の削除(Delete Issues)」**)。権限が足りないチケットは一括変更の対象から自動的に除外される

## 6. 自動化(Automation for Jira)

「条件を満たしたら自動でアクションを実行する」ルールを組める機能(Jira Cloud標準搭載)。

- 例:「ステータスが『完了』になったらウォッチャーにコメント通知」「期限が3日後に迫ったら担当者にメンションコメント」「特定ラベルが付いたら自動でエピックにリンク」
- プロジェクト設定 →「自動化」からルールビルダー(トリガー/条件/アクション)で作成。コード不要
- 定型の「チケット起票時のチェックリスト追加」「クローズ時の自動アーカイブ」などをルール化すると、手動の運用ミスが減る
- 必要な権限:**「プロジェクトの管理」**(プロジェクトスコープの自動化ルール作成)。サイト全体スコープのルールはJira管理者権限が必要

## 7. カスタムフィールドとスクリーン

チケットに独自項目(例:「影響範囲」「起票元」)を追加する機能。SCM/PMが集計・分類の軸を増やしたいときに使う。

- カスタムフィールドを増やしすぎると入力の手間が増え、結局埋められずに形骸化しがちなので、**JQLで絞り込みたい/レポートで集計したい軸だけ**に絞って追加するのがおすすめ
- 必要な権限:カスタムフィールドの作成・スクリーンへの配置は**Jira管理者権限**が必要(プロジェクト権限では不可)。プロジェクトのSCM/PMが管理者を兼任していない場合は、サイト管理者に依頼する

## 8. ロードマップ / タイムライン

エピック・チケットを時系列(ガントチャート風)で見る機能。依存関係のある大きめの計画を関係者に説明するときに使う。

- ソフトウェアプロジェクトのサイドバー「ロードマップ」またはタイムライン画面から利用
- スプリント予定と依存関係を一緒に見せられるので、PO/ステークホルダー向けの説明資料としてそのまま使える
- 必要な権限:**「参照」**があれば閲覧可能。エピック/日付の編集には**「課題の編集」**

## 9. 権限まとめ表

| 機能 | 最低限必要な権限 |
|---|---|
| フィルタの作成・保存(自分用) | 参照(Browse Projects) |
| ボードの閲覧 | 参照 |
| ボード設定・クイックフィルタ変更 | プロジェクトの管理(Administer Projects) |
| ダッシュボード/ガジェット | 対象プロジェクトへの参照 |
| 一括変更(編集・遷移) | 課題の編集(Edit Issues)+該当ワークフロー遷移権限 |
| 一括削除 | 課題の削除(Delete Issues) |
| 自動化ルール(プロジェクトスコープ) | プロジェクトの管理 |
| カスタムフィールド作成 | Jiraサイト管理者 |
| ロードマップ閲覧 | 参照 |

SCM/PMのロールであれば「プロジェクトの管理」まで持っておくと、ボード設定・自動化・クイックフィルタの大半を自分で完結できる。カスタムフィールドの追加だけはサイト管理者への依頼が必要になることが多い。
